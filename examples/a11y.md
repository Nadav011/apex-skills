# a11y — Real-World Examples

The skill enforces WCAG 2.2 AAA accessibility: ARIA patterns, 44×44 px touch targets, focus management, keyboard navigation, and RTL accessibility for Hebrew/Arabic UIs.

## Before / After

### Example 1: Icon button missing accessible name and touch target

**Before** (triggers the skill):
```tsx
// ❌ Icon-only button with no label — screen reader announces nothing useful
function CloseButton({ onClose }: { onClose: () => void }) {
  return (
    <button
      onClick={onClose}
      className="h-6 w-6 text-gray-500 hover:text-gray-900"
    >
      <X className="h-4 w-4" />
    </button>
  );
}
```

**After** (skill-compliant):
```tsx
// ✅ Accessible name via aria-label, 44px touch target via ::before expansion
function CloseButton({ onClose }: { onClose: () => void }) {
  return (
    <button
      onClick={onClose}
      aria-label="סגור חלון"
      className="relative h-6 w-6 text-gray-500 hover:text-gray-900
                 before:absolute before:top-1/2 before:start-1/2
                 before:-translate-x-1/2 before:-translate-y-1/2
                 before:h-11 before:w-11"
    >
      <X className="h-4 w-4" aria-hidden="true" />
    </button>
  );
}
```

**Why:** Without `aria-label`, a screen reader announces "button" with no context. The visual size (24 px) is well below the WCAG 2.5.8 minimum of 24×24 px and the recommended 44×44 px touch target. The `::before` expansion technique grows the tap area without altering the visual design.

### Example 2: Async form without live regions

**Before** (triggers the skill):
```tsx
// ❌ Error and success states update silently — screen readers never hear them
function NewsletterForm() {
  const [status, setStatus] = useState<'idle' | 'loading' | 'success' | 'error'>('idle');

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setStatus('loading');
    try {
      await subscribeEmail(new FormData(e.currentTarget));
      setStatus('success');
    } catch {
      setStatus('error');
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" name="email" placeholder="your@email.com" />
      <button type="submit" disabled={status === 'loading'}>
        {status === 'loading' ? 'שולח...' : 'הרשמה'}
      </button>
      {status === 'success' && <p className="text-green-600">נרשמת בהצלחה!</p>}
      {status === 'error' && <p className="text-red-600">שגיאה, נסה שוב</p>}
    </form>
  );
}
```

**After** (skill-compliant):
```tsx
// ✅ Live regions announce state changes to screen readers
function NewsletterForm() {
  const [status, setStatus] = useState<'idle' | 'loading' | 'success' | 'error'>('idle');

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setStatus('loading');
    try {
      await subscribeEmail(new FormData(e.currentTarget));
      setStatus('success');
    } catch {
      setStatus('error');
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email" className="sr-only">כתובת אימייל</label>
      <input id="email" type="email" name="email" placeholder="your@email.com" />
      <button
        type="submit"
        disabled={status === 'loading'}
        aria-busy={status === 'loading'}
      >
        {status === 'loading' ? 'שולח...' : 'הרשמה'}
      </button>
      {/* role="status" = polite for success; role="alert" = assertive for errors */}
      <div role="status" aria-live="polite" aria-atomic="true">
        {status === 'success' ? 'נרשמת בהצלחה!' : ''}
      </div>
      <div role="alert" aria-live="assertive" aria-atomic="true">
        {status === 'error' ? 'שגיאה בהרשמה, אנא נסה שוב.' : ''}
      </div>
    </form>
  );
}
```

**Why:** Sighted users see the color-coded message, but screen readers skip dynamically injected DOM nodes unless a live region was present before the update. `role="status"` (polite) lets the reader finish the current sentence before announcing success; `role="alert"` (assertive) interrupts immediately for errors, which is the appropriate urgency level.

### Example 3: Modal without focus trap

**Before** (triggers the skill):
```tsx
// ❌ Modal renders but focus stays on the trigger — keyboard users can't reach content
function ConfirmModal({ isOpen, onConfirm, onCancel }: ModalProps) {
  if (!isOpen) return null;
  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/50">
      <div className="w-96 rounded-xl bg-white p-6">
        <h2>האם אתה בטוח?</h2>
        <p>פעולה זו אינה ניתנת לביטול.</p>
        <div className="mt-4 flex gap-3">
          <button onClick={onConfirm}>אשר</button>
          <button onClick={onCancel}>ביטול</button>
        </div>
      </div>
    </div>
  );
}
```

**After** (skill-compliant):
```tsx
// ✅ Focus trap, aria-modal, focus restoration on close
import { useFocusTrap } from '@/hooks/useFocusTrap';

function ConfirmModal({ isOpen, onConfirm, onCancel }: ModalProps) {
  const trapRef = useFocusTrap(isOpen);

  if (!isOpen) return null;
  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/50">
      <div
        ref={trapRef as React.RefObject<HTMLDivElement>}
        role="dialog"
        aria-modal="true"
        aria-labelledby="modal-title"
        className="w-96 rounded-xl bg-white p-6"
      >
        <h2 id="modal-title">האם אתה בטוח?</h2>
        <p>פעולה זו אינה ניתנת לביטול.</p>
        <div className="mt-4 flex gap-3">
          <button onClick={onConfirm}>אשר</button>
          <button onClick={onCancel}>ביטול</button>
        </div>
      </div>
    </div>
  );
}
```

**Why:** Without a focus trap, pressing Tab exits the modal overlay and reaches background elements — unusable for keyboard-only users. `role="dialog"` + `aria-modal="true"` tells screen readers to suppress background content. `useFocusTrap` cycles focus within the modal and restores it to the triggering element on close, satisfying WCAG 2.1 Success Criterion 2.4.3.
